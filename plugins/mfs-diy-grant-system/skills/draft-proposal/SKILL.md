# Draft a Proposal

Write a funder-ready draft from the organization's own approved content.

Apply organization-profile and grant-guardrails throughout.

## Inputs

- The funder's questions with limits, and the guidelines (from start-grant, or ask for them)
- Master Grant Narrative (always read the current version from file storage or the Claude Project files). If there is none, say so and offer to build one with master-grant first. If the user wants to go ahead without it, draft from the documents they share and use more placeholders.
- Theory of Change
- Program Data for the programs involved
- Project budget, if one exists (from grant-budget)
- Past proposals to this funder, if any
- Anything new the user shares: updated numbers, staff changes, notes

If the questions are missing, ask for them before drafting.

## Step 1: Plan the response

1. Identify the reviewer type from the Master Grant Narrative's Audience Personas, or from the funder's type if there is no master grant (community foundation or United Way, corporate, specialty, government, family or faith foundation). Use that persona's expectations and tone.
2. Read the funder's priorities from the guidelines and match each one to a program, outcome, or fact in the Master Grant Narrative.
3. List any question the Master Grant Narrative cannot answer. Tell the user before drafting, so they can supply it or accept a placeholder.

## Step 2: Draft

- Answer every question in the funder's order, using the funder's headings.
- Build each answer from the Master Grant Narrative. Adapt the wording to fit the question and the funder; do not change facts.
- **Grant Summary or abstract:** follow the Master Grant Narrative's formula: the problem, the solution, the impact (including who will be served), then the request (amount, use, and number served).
- **Needs statement:** move from state or national data to local data, then to how the organization responds. Use the sourced statistics in the Master Grant Narrative or the Grant Data Sources folder first.
- **Outcomes:** use the Theory of Change outcomes, worded as approved. Outputs first, then outcomes.
- Use official program names and approved terminology.
- Keep each answer within its limit. Show the word or character count after each answer as `(312 / 350 words)`.
- For an LOI, keep to the funder's limit, or two pages if none is given.

## Step 3: Hand the draft back

Create the draft as a document named "[Funder] [Year] [Proposal or LOI] - Draft", saved as described in organization-profile.

After the draft, give the user:

1. Every placeholder, as a checklist
2. Any statistic more than three years old
3. Anything you adapted from a past proposal that should be rechecked
4. A Sources Cited list

Then suggest review-before-submit once the user has filled in the gaps.

## Shortening or tailoring

When the user asks to cut an answer to fit, keep the outcomes, numbers, and the request. Cut background and repetition first. Show the new count.
